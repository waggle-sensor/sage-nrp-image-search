# Authentication

Sage Image Search requires credentials for three external services. Without them, images cannot be indexed or displayed, and models cannot be downloaded.

## Required credentials

| Credential | Environment variable | Used by | Purpose |
|------------|---------------------|---------|---------|
| Sage username | `SAGE_USER` | weavloader, Gradio (K8s) | Authenticate to SAGE object storage |
| Sage password | `SAGE_PASS` | weavloader, Gradio (K8s) | Authenticate to SAGE object storage |
| Hugging Face token | `HF_TOKEN` | Triton, Weaviate init | Download gated ML models |

## Optional credentials

| Credential | Environment variable | Used by | Purpose |
|------------|---------------------|---------|---------|
| NRP API key | `NRP_API_KEY` | weavloader | Caption generation via NRP AI Gateway |
| NRP API endpoint | `NRP_API_ENDPOINT` | weavloader | NRP AI Gateway URL |
| NRP LLM model | `NRP_LLM_MODEL` | weavloader | Model name for NRP captioning |

NRP credentials are required when `LLM_RUN_MODE=NRP` (the default in Kubernetes dev/prod overlays). When `LLM_RUN_MODE=TRITON`, captions are generated by the on-cluster Triton VLM instead.

## Sage credentials

Your Sage account must have access to the images you want to index and search. Images you cannot access are **skipped during ingestion** and will not appear in search results.

- Set `SAGE_USER` and `SAGE_PASS` in your `.env` file for local Docker Compose.
- In Kubernetes, create the Sage user secret from the template. See [kubernetes/README.md](../kubernetes/README.md).

```bash
cp kubernetes/base/sage-user-secret.template.yaml kubernetes/base/._sage-user-secret.yaml
# Edit with base64-encoded SAGE_USER and SAGE_PASS
```

Generate base64 values:

```bash
echo -n "your_username" | base64
echo -n "your_password" | base64
```

> Secret files used in deployment must be named with a leading `._` prefix per `.gitignore` and must not be committed to version control.

## Hugging Face token

Triton downloads CLIP and Gemma model weights from Hugging Face at startup. Your token needs access to the models configured in [`.env.example`](../.env.example) and [`triton/entrypoint.sh`](../triton/entrypoint.sh).

- Set `HF_TOKEN` in your `.env` file for local Docker Compose.
- In Kubernetes, create the Hugging Face secret from the template:

```bash
cp kubernetes/base/huggingface-secret.template.yaml kubernetes/base/._huggingface-secret.yaml
# Edit with base64-encoded HF_TOKEN
```

## NRP AI Gateway credentials

When captioning runs through the NRP AI Gateway (`LLM_RUN_MODE=NRP`):

```bash
cp kubernetes/base/nrp-llm-user-secret.template.yaml kubernetes/base/._nrp-llm-user-secret.yaml
# Edit with base64-encoded NRP_API_ENDPOINT and NRP_API_KEY
```

## Local Docker Compose setup

```bash
cp .env.example .env
```

Edit `.env` and fill in at minimum:

```
SAGE_USER=your_username
SAGE_PASS=your_password
HF_TOKEN=your_hf_token
```

Then start the stack:

```bash
docker compose up -d --build
```

> **Note:** The Gradio UI container in `docker-compose.yml` does not include `SAGE_USER`/`SAGE_PASS` by default. Image thumbnails may not display locally unless you add these variables to the gradio-ui service.

## Access control limitations

Today, access control works as follows:

- **Indexing:** Images you lack Sage access to are skipped.
- **Query filtering:** Results from nodes in `UNALLOWED_NODES` are removed.
- **No per-user ACL:** The system does not yet enforce Sage permissions per user at query time. Per-user authorization is planned for a future data API integration.
